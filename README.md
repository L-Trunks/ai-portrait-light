# ai-portrait-light

**给任何文生图模型写人像光线提示词的方法论。**
~280 张同种子单变量对照 + 十一批成品迭代（约 480 张候选，人工挑出 30 张，其中四批整组推倒）打出来的，装成一个 Claude Code / Claude Desktop 的 skill。

> *A model-agnostic methodology for writing portrait-lighting prompts, derived from
> ~280 single-variable A/B renders plus eleven rounds of human-curated finals. Prompts are full-sentence Chinese — they work as-is
> in Doubao / Jimeng / Qwen as well as local ComfyUI. English summary: [README.en.md](README.en.md)*

一句话版：

> **别写「唯美的逆光」，去写「太阳在她左前方 45 度的两栋楼之间压得很低，正斜劈在她的半张脸上」。**

其余所有规矩都是这一句的推论 —— 它一句话做完三件事：**写场景不写形容词**、
**钉方位角**（不是「和脸一样高」）、**打脸而不只是镶边**。

⚠️ 早期版本这句写的是「太阳……在她身后两栋楼之间的缝里、**和她的头一样高**」。
那是**镶边光**，物理上没错，但后来八张实拍全毙 —— **只镶边不打脸 = 人不美**。已经换掉。

## 装

```bash
git clone https://github.com/L-Trunks/ai-portrait-light.git
cd ai-portrait-light
bash install.sh            # Windows: powershell -ExecutionPolicy Bypass -File install.ps1
```

装到 `~/.claude/skills/`，之后跟 Claude Code 说一句「帮我写个逆光人像的提示词」就会触发。
加 `--project` 则只装到当前项目。

**不用 Claude 也能用** —— 直接读 [`skills/portrait-light/SKILL.md`](skills/portrait-light/SKILL.md)，
它本身就是一份可以照着抄的方法论文档。提示词是纯中文整段，不用拆词、不用配负向。

## 这份是方法论，不是某个模型的参数表

规律按「换模型还成不成立」分成两半，SKILL.md 里是分开写的：

- **换模型也成立**（构图和光学层面）：光靠场景写、**先定光位**、光源的距离方位和支架、
  **名词自带语义那条定律**、空气要有介质、补色对、**六条画面级判据**、构图比光更强、
  三种构图族各自的写法。
- **换模型要重验**（和采样器 / 条件机制绑定）：cfg=1 的负向失效、字数与景别的关系、
  seed 的可复现性。

证据是在本地 ComfyUI + z-image 上打的，但**除了上面第二类，其余都不依赖这个模型**。

## ⭐ 最贵的一条：这是**两道独立的关**

**光对了 ≠ 好看。** 一组十张里，有三张的边光、贴身光源、补色对**全部成立**，
交出去一张没留下 —— 差的全在第二关。六轮迭代里，**有三轮是"光完全正确但整组被毙"**。

| | 第一关：光对不对 | 第二关：好不好看 |
|---|---|---|
| 解决什么 | 有没有光、光在不在该在的地方 | 这张图值不值得看 |
| 判据 | [SKILL.md §1 七步](skills/portrait-light/SKILL.md) | [SKILL.md §2 六条](skills/portrait-light/SKILL.md) |
| 最容易漏 | **先定光位**：逆光只镶边不打脸 = 人不美 | **背景要"少而大"且带一条几何线** |

⭐⭐ 第二关里最有分辨率的一条 —— 把被选中的和被砍掉的并排比，**唯一 100% 分得开的是背景**：

| | 选中的 | 被砍的 |
|---|---|---|
| 背景 | 海+天 / 一整面暗墙 / 暮蓝天 / 雪街 —— **元素少、块面大** | 夜市摊档 / 一堆糊光斑 / 观众席人头 / 一片碎树干 |
| 几何线 | 窗棂格 / 海面反光带 / 木马顶棚弧线 / 花架长廊 / 桥架透视 / 梯田曲线 | **一条都没有** |

⛔ **细碎堆叠的背景，虚化解决不了** —— 它给的是"信息量"不是"结构"。
⭐ 两个出片率最高的配方：**太阳盘 + 水面反光带**（反光带本身就是一条从光源直指人的引导线）、
**长廊 / 隧道尽头的光源**（花架、樱花隧道、鸟居）。

## ⛔⛔ 最容易用错这份方法论的方式：把每一条都套在每一张上

发布之后又打了 5 批 60 条、180 张候选，最大的一个发现是**判据清单不是施工单**：

| 做法 | 挑中率 |
|---|---|
| 每条都上满（打脸四件套 + 几何线 + 黑锚 + 补色对 + 皮肤档 + 成像句），第一批 | **7/12** |
| 同一套骨架换穿搭换场景再来一批 | **1/12** |
| 再来一批（主光全换冷光）| **1/12** |
| 改成**每张只定一个「成立点」**，其余留白 | **6/12** |
| 同上，连出第二批 | **4/12** |

⛔ **一套骨架只能撑一批。** 上满本身不是错的（第一批 7/12 是全场最高），
错的是拿同一套骨架连出第二批 —— 注意力全花在填满六项判据上，
**动作和机位就退化成默认值**：那批 12 条里 10 条的动作是同一句「转过头看向镜头」，12 条机位全是平视。
第二批要换成立点，或者换一整个轴（画幅 / 色温 / 成像系统），光换穿搭和场景不够。

⭐ 「成立点」= 这张图**靠什么撑住**，一两个词，写在动笔之前：
场景+镜头（昆虫视角从花丛缝隙里看她）/ 光线+妆面 / 场景关系+成像方式 / 道具+光线 / 成像方式+场景。

⭐ 另外两条同期加进去的：
- **逆光只镶边不打脸 = 人不美。** 光必须落到脸上，四件套缺一不可：
  亮面 + 暗面 + **鼻侧的三角亮斑** + **睫毛投在被照亮那半边脸颊上的影子**。
- **成像系统是独立于光的第三个轴**（数码 85mm / VHS / CCD / 直闪 / 胶片 / 柔雾），
  一张图只能有一个。判据是：**这个场景现实里会不会真有人开闪光灯。**

## ⭐⭐ 一条能预测新坑的定律：名词自带的语义压过形容词

> **模型先按名词的常识把东西放好，再读你的形容词。
> 形容词只能微调，推不动名词自带的位置 / 高度 / 数量 / 时间 / 属性。**

同一跤栽过六次，每次都是"形容词连改数版无效、换个名词一次成立"：

| 名词带进来的 | ⛔ 压不住 | ✅ 换名词 |
|---|---|---|
| 灯具的高度 | 「路灯，灯头和她的头一样高」→ 顶光 | 矮墙上的马灯 / 灯笼 / 营灯 |
| 招牌装在楼上 | 「霓虹灯箱招牌，比她高出一头」→ 挂到二楼 | **自动贩卖机** / 橱窗灯箱 |
| 量词的排布 | 「一**串**红灯笼」→ 光源跑到两侧 | 单数 + **给画面里的尺寸** |
| 镜头的位置 | 「灯泡在她正前方、和脸一样高」→ 被挪到身后 | 侧前 45°（方位角）/ 正前偏下（高度差）|
| 时间里有没有太阳 | 「**黄昏**的坡」→ 只剩余晖天，太阳没进画 | 「**日落**」+「太阳是一个明晃晃的圆盘」 |
| 因果被当成妆容 | 「脸颊被冻得有点红」→ 两坨腮红 | 别写因果，写皮肤本身的质地 |

⭐ 用法：写完一句先问 **这个名词本身带不带位置 / 高度 / 数量 / 时间的常识？**
带、而且和你要的相反 → 现在就换名词。

## 另外几条最贵的结论

**① 光是靠场景写出来的，不是靠形容词。**
五档强度的光线形容词堆在句尾，三项指标纹丝不动；
只把场景句从「身后是干净的暖白色墙面」换成「身后是敞开的店门和门外的街道」，逆光一次就出来。
因为墙把太阳挡在画框外了 —— **要把场景写成物理上只能这么打光。**

**② 光源的距离和方位都要钉死，而且只剩两种写法。**
「整片城市霓虹就在她身后」——霓虹在几百米外，落到人身上的光约等于零，出来是**好看的背景板**。
⛔⛔ **「和她的脸／头一样高」整档废掉** —— 那是**镜头**的高度，模型只能把光源往她身后挪。
只有两种写法没翻过车：**侧前方 45°**（写方位角）和**正前偏下**（写高度差，「比她的脸低半米」）。
唯一的例外是**正后方的真逆光**。
⛔ 还有一整族反直觉的坑（灯具高度 / 招牌高度 / 量词 / 镜头位 / 时间词 / 支架高度），
都是上面那条**名词语义定律**的实例 —— 支架那条还要补一句：它必须**比她高**且**在两米内**
（齐胸的花穗托不住太阳，几十米外的石雕等于没有）。

⚠️ 而「正后方」这条只对能透光的浅色主体成立；一身黑的角色钉正后方会变成剪影，
得让光源偏一侧、再逐条点名亮线落在哪几条边上。

**③ 每张给一组补色对。**
光已经对了但画面还是平，九成是因为整张图只有一个色温。
暖橘钠灯 ↔ 冷蓝雪夜、火橘 ↔ 夜蓝、蓝紫射灯 ↔ 暖橘荧光棒、冷蓝银河 ↔ 暖黄营灯。

**④ cfg=1 时没有「不要」。**（模型相关：所有开了 Lightning / turbo / 蒸馏的模型）
负向提示词形同虚设，填了不报错、只是不生效。所有禁止项必须**正向化写成肯定句**：

| 想要 | ⛔ 写不出来 | ✅ 正着写 |
|---|---|---|
| 不要投影 | 负向填 `shadow` | 每个物体都直接贴在白纸上，不产生任何投影 |
| 脸别太圆 | 「脸不胖」 | 窄长的鹅蛋小脸，脸颊平顺内收、下颌角收窄，下巴是尖的 |
| 短裙别变连体衣 | 「不是连体衣」 | 裙筒是完整闭合的一圈、四周一样齐地把大腿包住 |

规律叫「可选结构改成不可选」：**`没有X` 是在召唤 X。**

## 三种构图族，规律互相矛盾

最容易翻车的地方 —— 很多人把「发丝光」的写法套到全身照上，怎么写都不出来。

| | 特写 | 近景 / 半身 | 环境人像（横幅）|
|---|---|---|---|
| 靠什么成立 | 暗部托脸 + 贴脸的光源 | 构图（人偏一侧 + 背景全糊）| 场景几何 + **贴身**主光 |
| 背景 | 正向写死「糊成一片没有细节」 | 同左 | 反过来：**要有细节** |
| 画幅 | ⛔ 只能竖幅 | 都行 | ⛔ 只能横幅 |
| 最容易废在 | 画框收不住，退成胸像 | 背景抢戏 | 退化成「好看的背景板」|

⛔ **横幅压不住特写**：同一句特写相机在 16:9 下连改三版、十二张出图景别一寸没动；
换成竖幅一次到位。16:9 的画框本身就在要求横向填充。

## ⚠️ 两条免责

**数值全对也可能是废片。** 这套里有八个量化指标，但它们只能证伪不能证真 ——
数值最漂亮的那组是「人身上一点光都没有的好看背景板」，这条踩过三次。
**唯一可靠的验收是肉眼看：发丝有没有一根根亮起来、人身上有没有轮廓光。**

**挑片比改措辞收敛快。** 同提示词换种子的摆幅，比绝大多数措辞改动都大 ——
这 30 张是**约 480 张候选、十一批迭代**里挑的，**每个位置都换掉了默认那张**。
同一个方向改过三次还没动，说明卡的是构图或画幅这类结构性的东西，该换概念了。
